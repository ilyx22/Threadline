# SOP 09 - Capacity / Delegation Gate

## Trigger
>=2 active clients with real load data, OR founder feels capacity pressure, OR acquisition is being reduced because fulfilment/admin is consuming time.

## Objective
Decide whether to delete, automate, delegate, hire or deliberately cap sales - using measured work rather than vibes.

## Step 1 - Load audit
For each recurring task record:
- frequency;
- founder/operator/editor minutes;
- judgement level;
- client dependency;
- error/rework rate;
- whether revenue/value depends on it.

## Step 2 - Apply order of operations
1. **DELETE** - does this need to exist?
2. **SIMPLIFY** - can the output/approval step be reduced?
3. **AUTOMATE** - only after manual process is understood and safe.
4. **DELEGATE** - if clear enough to teach/QA.
5. **HIRE** - only when stable recurring workload justifies role economics.

## Step 3 - Capacity calculation
Estimate sustainable clients at current measured load, including buffer for sales/admin/incidents. Do not use the old 5-8h/client assumption if actual data differs.

## Step 4 - Hiring gate
Before hiring an operator:
- founder has personally run process;
- SOP exists or can now be created from proven workflow;
- role has enough recurring work;
- cost/margin is acceptable;
- QA owner is clear.
Editor bench can precede operator because editing is already a discrete craft function.

## Step 5 - Decision
Record one: HOLD / DELETE WORK / AUTOMATE / CONTRACTOR / HIRE / RAISE PRICE / REDUCE SCOPE / CAP SALES.

## Definition of done
Capacity decision is based on real Delivery Load Ledger data, with one owner and next action.
