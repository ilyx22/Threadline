# SOP 06 - Weekly Delivery Cycle

## Trigger
Client has completed installation and is active.

## Objective
Run one predictable weekly content-growth learning cycle without making the founder the project manager.

## Monday - Intelligence + learning
1. Pull new market/customer/competitor evidence.
2. Pull prior content/performance/commercial signals.
3. Review sales-call/commercial notes received from client.
4. Approve/reject candidate signals.
5. Revisit primary constraint only if evidence materially changed.
6. Produce ranked recommended tests.

## Tuesday - Strategy + scripts
1. Select tests/ideas.
2. Draft scripts/outlines.
3. Claim/source check.
4. Voice/offer-alignment QA.
5. Build recording queue in client priority order.

## Wednesday - Recording
1. Client records approved queue.
2. Threadline checks missing takes/audio/focus/claims quickly.
3. Collect raw files in agreed structure.
4. Handoff to editor with clear brief.

## Thursday - Production + approval
1. Editor returns first pass.
2. Internal Threadline QA before client sees it.
3. Consolidate client approval batch.
4. Log revision reason; avoid endless subjective back-and-forth.
5. Move approved assets to package/schedule state.

## Friday - Distribution + learning
1. Publish/schedule manually or via supported integration.
2. Store final package/live URL/date.
3. Update performance/commercial signals when available.
4. Capture any proof using SOP 08.
5. Send concise useful weekly update if client needs it: shipped / learned / next / needs-you.
6. Update Delivery Load Ledger with actual founder/operator/editor minutes.

## Always-on client dependencies
- sales-call/customer feedback;
- business/offer changes;
- timely recording;
- timely approvals;
- proof/sales outcomes Threadline cannot observe automatically.
Use portal task/action queue so these asks are visible.

## Escalation conditions
- two missed recording/approval SLAs;
- repeated footage quality failure;
- >2 revision cycles repeatedly;
- scope creep;
- no usable source/commercial feedback for multiple cycles;
- delivery time materially above target.
Document, discuss, and solve the actual constraint rather than quietly absorbing it.

## Definition of done for the week
A complete evidence -> strategy -> production -> live/ready -> learning cycle is moved forward and load data is recorded.
